# Schemas — contract payload, event ledger, config

## Contract payload (daily) — `dhriti ritual` (schema v2)

```json
{
  "mandatory_task": "Reverse an array in Java (in-place, then print)",
  "smallest_next_action": "open ReverseArray.java and write the swap loop header",
  "evidence": [
    {"kind": "command"},
    {"kind": "file", "accept_nonzero_exit": false}
  ],
  "targets": [
    {"kind": "session_count", "count": 1},
    {"kind": "evidence_accepted", "count": 1}
  ],
  "allowed_tools": ["docs.oracle.com"],
  "blocked_tools": [],
  "core_belief": "I am becoming a backend engineer",
  "identity_statement": "I am someone who ships code daily",
  "work_mode": "closed_world",
  "main_belief": "I want to be a software engineer",
  "main_belief_metric": "pass the CS course; ship a working project",
  "main_belief_current_state": "I am behind on the course and avoiding the compiler",
  "substitute_activities": ["guitar practice", "multiplayer games"],
  "substitute_budget": "3 hours per week",
  "expected_obstacle": "the reverse loop throws IndexOutOfBounds",
  "if_then_response": "check the loop bounds against the array length",
  "return_condition": "rerun the test after the fix",
  "research_fallback": {"scope": "Spring Security JWT for the failing test",
                        "return_condition": "rerun the test"},
  "emergency_policy": "medical, family, or the laptop is on fire"
}
```

Rules (enforced in `contract.validate_payload`):
- `mandatory_task`, `smallest_next_action`, `evidence`, `core_belief`,
  `identity_statement` are required — the ritual refuses incomplete
  contracts.
- **D-030 group (required):** `main_belief`, `main_belief_metric`,
  `main_belief_current_state`, `substitute_activities`,
  `substitute_budget` — validated as a unit; the failure state is the
  signal, not a slogan.
- **IF–THEN group (optional, all-or-nothing):** `expected_obstacle`,
  `if_then_response`, `return_condition`; `research_fallback`, when
  present, must carry `scope` and `return_condition` (bounded
  allowance, not a browsing exemption).
- `emergency_policy` (D-019) names what counts as an emergency; the
  emergency path exists regardless, the sentence makes it honest.
- evidence kinds: `command` (exit code checked), `file` (hash),
  `manual` (kept, never proof), `observed` (adapter events).
- `accept_nonzero_exit: true` honors documented-failure proof
  (PDF 6.1: a failed attempt with a recorded error is progress).
- After sealing: immutable (DB trigger). New drafts supersede; sealed
  contracts are never edited or deleted.

## New tables (v2, additive — the hash chain keeps old rows immutable)

- `parking_lot(id, created_at, session_id, day_id, question, origin,
  disposition parked|approved|dropped|explored, disposition_at,
  disposition_note)` — the wall's mail slot.
- `cold_review(id, created_at, scope day:<date>|week:<monday>,
  question_key, answer, day_date)` — six fixed questions; answer text
  is bootcamp-scoped and never enters the chain (only question keys).

## Event ledger — dossier 7.2 schema, verbatim

| Column | Meaning |
|---|---|
| `event_id` / `seq` | identity + order |
| `occurred_at_utc` | ISO-8601 UTC (never local) |
| `monotonic_offset_ms` | monotonic clock alongside (clock-change forensics) |
| `session_id` / `case_id` | work-unit / analysis-case grouping |
| `source_adapter` / `source_version` | provenance |
| `event_type` | e.g. contract_sealed, session_active, browser_navigation, evidence_submitted, day_state_changed, adapter_arm_failed |
| `parent_event_id` / `process_instance_id` | lineage (GUIDs where available, never bare PIDs) |
| `observed_payload` / `raw_payload_reference` | observed facts only |
| `inference_payload` / `model_id_or_rule_version` | inferred content — a separate column, never mixed |
| `policy_version` | which frozen snapshot was active |
| `action_taken` | allow/block/warn/logged/disclosed |
| `telemetry_quality` | OK / MISSING / DEGRADED / SUSPECT |
| `prev_hash` / `row_hash` | the chain (see below) |

Hash chain: `row_hash = SHA256(prev_hash + SHA256(canonical_json(payload)))`.
Anchors checkpoint the head so a single hash can be kept off-machine.
`dhriti verify` recomputes the whole chain.

## Config — `~/.dhriti/dhriti.config.json`

Generated by `dhriti init` from the defaults in
`dhriti/constants.py` (deep-merged, so a user config can be partial).
Key sections: `timezone`, `day_window` (start/day_close/end),
`break_glass` (delay_seconds, cooldown_hours, min_reason_chars,
penalties), `bridge` (host/port/token_file/policy_ttl_minutes),
`enforcement` (level, required_adapters), `adapters.*` (the
placeholder toggles), `taper` thresholds, `research_pass` defaults.

## Tier configs

`configs/tiers/` holds lite.json / standard.json / research.json —
overlay fragments matching dossier 11.1 (Lite is what v1 runs;
Standard adds Sysmon + ActivityWatch + PM4Py; Research adds Screenpipe
trial + embedding experiments once labels exist).
