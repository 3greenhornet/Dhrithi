# Behavioral pattern taxonomy — the subject's own reference

**Origin:** Specimen 001 (`procrastination attempt1.pdf`), final phase
(`pattern_collection`). The subject asked the AI for this list explicitly
("write 10 points properly", "note and categorise them to identify well …
in detail and emphasise please than listing") — twice. The list was
produced inside the specimen but was never carried into the project.
This file delivers it as a first-class artifact, in the subject's own
words where the specimen records them, mapped to the systems that can
use it: the labeling guide, the cold review, the digest reader, and
future specimen coding.

**Status:** reference vocabulary. It is NOT policy (D-014 stands: no
pattern recognition acts in-session). Patterns are named only in cold
state — in coded specimens, in review answers, in cold analysis. Naming
a pattern hot is itself P-02.

**Naming convention:** `P-01` … `P-10`. Cite as `P-xx` in specimen
findings and review notes.

## The patterns

| ID | Name | The subject's own description (specimen wording) | Structural signature (what telemetry can see) |
|---|---|---|---|
| P-01 | Intellectualization | "turn a simple task like coding into a grand discussion about media, psychology, evolution, and philosophy. It feels deep, but it keeps you from the keyboard" | long sessions in high-fluency domains (chat, reading, video essays) with zero evidence-class events |
| P-02 | Meta-recursion | "You analyze your procrastination, then analyze the analysis, then ask about the pattern of analyzing the analysis. | P-03 | Curiosity-chain branching | "One question leads to another: movie → anime → tropes → psychology → dating → media → AI → attention → 'why am I like this?' | P-04 | Grandiose escapism | "when the coding task becomes too real, you pivot to 'Let's build a world-changing app.' It feels noble and important, but it is a way to avoid a beginner-level exercise" | new project artifacts (repos, plans, specs) created while the day's target domain shows no execution events; the Dhriti origin moment itself (turns 32, 42) |
| P-05 | Validation seeking | "You ask 'How good am I?', 'Do you agree?', 'Did you figure it out yet?' You want approval, not action" | questions-about-self/questions-about-work ratio; testing an interlocutor (AI or human) for reaction rather than information |

| P-07 | Productive procrastination | "You watch videos about Java, read about developer experience, or discuss competence instead of writing code. | P-08 | Task substitution | "The real task is compiler practice. You substitute it with conversation, planning, categorizing patterns, and meta-analysis. | P-09 | All-or-nothing framing | "'Not for me, but for the world.' '90% audience / 10% stage.' You make the choice dramatic and huge, so a small 10-minute coding rep feels pointless" | target sizes set heroically then missed entirely; refusal to start small; the ramp-schedule answer (30→50→70% on-stage) exists for exactly this pattern |
| P-10 | Beginner-status shame avoidance | "the compiler exposes you as a beginner. The audience seat is safe. The stage is not" — "your mind is choosing the game it is already good at to protect you from the game where you might fail" | time concentrated in already-mastered domains (analysis, discussion, media criticism) whenever the target domain is available and unmet; errors avoided rather than submitted |

## The engine (how the patterns relate)

P-10 is the affective engine; P-01/P-07 are its favored vehicles because
they are the already-won games (P-10 note: "a game you have already
beaten a thousand times"). P-03 is the acquisition path, P-05/P-06 keep
the feed alive, P-04 and P-09 blow the task up to a size that guarantees
never starting, and P-02 metabolizes even the countermeasures — including
this project's own planning (R-001) and any future pattern-naming done hot.

## Rules for use

1. **Cold only.** Patterns are named in specimen findings, review answers
   (the user may self-apply a P-code), and cold analysis — never in any
   in-session surface, never in the wall, never in a notification.
2. **Never predictive.** A P-code describes a coded specimen or a
   submitted answer; it is never used to classify live behavior (D-014:
   no in-session classifier).
3. **Self-application is evidence.** When the user names a pattern in a
   review answer unprompted, that is `competence_source`-grade signal for
   the cold review; the pattern across weeks is what the digest reader
   should look at, not any single instance (the specimen's own ending is
   the warning: asking for the list twice was P-02/P-05 in action).
4. **One taxonomy, no forks.** Future specimens code against these ten
   plus new P-numbers (P-11…), never renames. A pattern that cannot be
   stated in one behavioral sentence is not a pattern.
